## Rulings made during the work (with their cost if wrong)

- T1→T4 - FfiEvent.Queued must be handled in Swift switch (exhaustive) - T4 text lists events without .queued: Ruling: T4 ignores .queued on the iPad (PC-only event) — cost if wrong: none
- Ruling: pushes to origin/v1/ios are a side effect needing owner OK; T1-T2 are local; stop before Task 3's first push if no OK yet.
- Task 2: Ruling: plan defect — the sender never gets a delivery event, so "clear on Received/Failed" leaves the notice up forever and Failed wipes other peers' notices. Event::Queued{peer,files} now means "files currently waiting for this peer", emitted on every change incl. 0; UI sets waiting[peer]=files — cost if wrong: one extra event per delivered batch
- Task 3: Ruling: transferFailed subtracts one instead of zeroing — Incoming/Received carry no transfer id so the failed transfer's remaining count is unknown; stale count only makes the app hold the node up to iOS's background limit — cost if wrong: up to ~30 s of extra background time after a failed multi-file transfer
- Task 3: Ruling: sweepIncomplete removes only .incoming folders older than 1 hour — the app can launch while the extension is mid-copy — cost if wrong: dead half-batches linger up to an hour, invisible to batches()
- Task 4: Ruling: device check (Step 6) moved to one combined session after Task 5, with the 0604513 artifact as fallback — saves a sideload (7-day re-sign, slot limits) — cost if wrong: Task 4 device bugs found after Task 5 is built on it
- Task 5: Ruling: Share/Info.plist generated by XcodeGen instead of a committed file (*.plist is gitignored for secrets) — cost if wrong: none
- Task 5: Ruling: C1 fix = BridgeKit appGroupCandidates(bundleId:) deriving the SideStore team suffix from the resigned bundle id, trying suffixed then bare id; parsing entitlements only if the device shows the id format differs — cost if wrong: one more CI + sideload round
- Final: Ruling: overrides Task 1 deferred minor (mid-transfer peer loss): a queued batch is dropped only on failures that will repeat ("can't read a file", "only files can be sent", "declined"); everything else stays queued, on PC and iPad — a permanently failing unknown error retries on each Hello while Bridge is open — cost if wrong: repeated resends until the owner clears it
- Final: Ruling: fix wave also takes M1 (.part sweep at cold launch) and the repeated background() guard, per reviewer triage — real device-visible bugs — cost if wrong: small diff
- Final: Ruling: M1 stays without an age check. The 1 h rule belongs to sweepIncomplete (extension mid-copy in the outgoing queues); .part in Documents is written only by core in this process and no node runs at Model.init. The re-review prompt misapplied the rule — cost if wrong: a .part from a live receive is deleted, which needs a second running app process
