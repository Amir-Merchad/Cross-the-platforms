# v1 Plan 4: iPad Swift App — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native iPad app, Bridge, that pairs with the PC by QR, receives files into Files → On My iPad → Bridge, sends files to the PC, and gets anything the PC queued while the app was closed.

**Architecture:** The app is a thin SwiftUI shell over the same UniFFI core as Android (`start_node(..., kind: PeerKind::Ipad, ...)`). iPadOS suspends apps, so the node runs only while the app is open: it starts on every foreground, and because `Node::start` announces itself (`Hello`) the PC learns at once that the iPad is back. A new core `Outbox` keeps sends to an unreachable iPad on the PC and delivers them on that `Hello`. Testable Swift logic lives in a pure SwiftPM package (`BridgeKit`) because the UI can't be run on Windows.

**Tech Stack:** Rust core + UniFFI 0.32, Swift 5.10+/SwiftUI, iOS 17, VisionKit `DataScannerViewController`, XcodeGen, GitHub Actions `macos-latest`, iloader → SideStore 0.7.0.

**Spec:** `docs/specs/2026-11-02-device-bridge-design.md` §4 (apps, no-Mac builds), §7 (iPad fallback), §8 (fast path, folders), §9 (iPad limits). Facts: `docs/spikes/results.md` (Spike 5/6, iPad section). Reference code: `apps/android/.../App.kt`, `ShareActivity.kt`; `spikes/ios-app/`; `.github/workflows/ios-spike.yml`.

**Out of scope:** LocalSend-protocol fallback (§8; the Outbox covers "app not open"), Tauri mobile (plan 5), iPad clipboard sync (already works with no app via `idevice`).

**Branch:** `v1/ios`, created from `v1/transfer`. Swift is only built and tested in CI, so this plan needs pushes to `origin/v1/ios` (owner approves that once, before Task 3).

## Global Constraints

- Never log file names or clipboard text (Swift and Rust): sizes, counts, timings, ids only.
- No Mac: every Swift check is a CI run. Keep the UI small; anything with logic goes in `BridgeKit` with tests.
- iOS deployment target `17.0`. Bundle id `dev.crosstheplatforms.bridge`, extension `dev.crosstheplatforms.bridge.share`, app group `group.dev.crosstheplatforms.bridge`, display name `Bridge`.
- Receive into the app's `Documents` (`UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace` → Files → On My iPad → Bridge). Node data in `Application Support/node`.
- Peers: send only to `PeerKind.windows`. Incoming `Clip` events are ignored on the iPad: `idevice` owns the iPad clipboard. The PC already sends clipboard text to Android peers only.
- The share extension never links the Rust core (extension memory limit); it only copies files into the app group.
- Queue only when the peer is `PeerKind::Ipad` and unreachable. Android behaviour doesn't change.
- Apple ID password: typed by the owner into iloader only, never in chat or CI.

## Review Focus

1. **iPad closed when the PC sends** → the PC says it's waiting, the file arrives next time Bridge opens, also after the PC restarted in between. Tests in Task 1.
2. **A queued file was moved or deleted before the iPad opened** → that batch reports a failure, later batches still go, the queue doesn't jam. Test in Task 1.
3. **App sent to the background mid-transfer** → the node stays up until the transfer ends or iOS's background time runs out, then stops cleanly and restarts on foreground. Tests in Task 3.
4. **Share extension killed mid-copy** → a half-copied batch is never sent and is swept on the next launch. Test in Task 3.
5. **Two shared files with the same name** → both reach the PC. Test in Task 3.
