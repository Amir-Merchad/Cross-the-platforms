# Base UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the plain UI of all three apps with the approved Bridge design, including every designed state.

**Architecture:** Small core additions first (transfer details, reachability, settings). Then the Windows hub is rebuilt around pure, unit-tested logic files (`desk`, `devices`, `activity`, `spring`) with thin React components on top. Android and iPad follow, each with one screen over the same vocabulary.

**Tech Stack:** Rust (`bridge-core`, UniFFI), Tauri 2, React 19, Tailwind 4, Base UI, vitest, Compose Material 3, SwiftUI, BridgeKit (SwiftPM).

**Spec:** `docs/superpowers/specs/2026-11-04-base-ui-design.md`. Visual source of truth: the Claude Design canvas linked there. Read its board for each screen before building it. Foundations holds tokens and motion values. Use its state names in code and tests.

## Global Constraints

- Branch `v1/ui`, stacked on `v1/ios`. Push only to `origin/v1/ui`. No merge and no PR unless the owner says so.
- Never force-kill `ctp-app`, `ctp-engine` or `ble-hid`. The owner quits from the tray. Ask before rebuilding into `target\debug` while the app runs.
- Never log file names, keys or clipboard text. New events reach the UI only: no `diag::log` of `name` or `paths`.
- Never run `git clean -X` or `-fdx`, or bare `git stash`. `pairing*` and `*.plist` are gitignored, with `core/src/pairing.rs` excepted.
- Do not read `rp-pairing.plist` contents. Do not change Windows security settings.
- No Mac: Swift is only checked by the `ios` workflow (jobs `kit`, `ipa`).
- Run `apps/android/build-rust.ps1` after any FFI change, before an Android build.
- `settings.json` keeps loading older files. Fields use the existing `#[serde(default)]`.
- Primary action `#FFC531`. Text on device colours `#10202E`. Device colours `#FF7A4D #23C48F #4DA9FF #F76CAE #FFC531`.
- Motion: pick up after 5 px at 107%; magnet range 170 px, pull 35%; file target range 34 px at 112%; file flight 300 ms; forget hold 900 ms; settle about 300 ms. Reduced motion makes all of it instant.
- Copy comes from the canvas and spec. Sentence case. Errors are a plain sentence plus what to do, never a raw error string.
- Input safety is unchanged: Esc three times and Ctrl+Alt+Q always work.

## Review Focus

1. A device that holds the keyboard and mouse is unplaced or forgotten: input returns to Windows first, and control is never stuck on a device that no longer has a position.
2. A monitor is unplugged while a device is attached to it: the attachment is kept and the device shows in the tray as "Screen not connected", then returns when the monitor does.
3. Quick changes in a row, such as two fast drags, or a drag right after changing the received folder: saves land in order, and an older save cannot undo `clipboard_sync` or `receive_dir`.
4. A blank or very long device name: the UI shows "Unnamed device" or truncates. It never shows a raw id and never breaks the layout.
5. A transfer row never stays stuck: a flush that stops, or a failure with an id the UI never saw, still ends in a visible result, and Waiting is correct after a hub restart.
